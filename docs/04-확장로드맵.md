# 4. 확장 로드맵

개인 도구에서 시작해 팀 공용 설정 저장소로, 그다음 표준 개발 프로세스로 넓힌다. 각 단계는 **다음 단계로 넘어가는 조건**을 미리 정해 두고, 조건을 채우지 못하면 넘어가지 않는다.

## 단계 요약

| 단계 | 범위 | 핵심 산출물 | 다음 단계 조건 |
|------|------|-----------|--------------|
| 1. 개인 검증 | 담당자 1~2명, 조회형 화면 | 효과 검증 결과, 게이트 시제품 | 01 문서 판단 기준 충족, 보안 부서 1차 의견 |
| 2. 팀 시범 | 개발팀 1개, 조회·단순 CRUD | 팀 공용 설정 저장소, CI 게이트 | 4~8주 운영, 결함률 유지, 사용자 만족도 |
| 3. 표준 편입 | 정보화본부 전체 | 개발 표준·검수 절차 개정, 게이트웨이 | 보안 승인, 운영 책임자 지정 |

## 1단계: 개인 검증 (현재)

- 7회차 시제품을 그대로 쓰되, 실데이터·자격증명 차단을 먼저 적용한다
- 이미 확인한 것: 공문으로 접수된 **AI 교과목 이수율 조회 화면**을 개인 스킬로 개발해 실업무에 반영했다. 예상 1주 작업이 반나절에 끝났다 ([01 문서 1.2](01-효과검증.md))
- 개인 스킬은 두 종류로 정리한다
  - **생성 스킬**: 내 코딩 베이스(정규식 처리, 공통 패턴, 화면·SP 기준 코드)
  - **설명 스킬**: 생성된 DB 설계·SP 중 이해가 안 되는 부분을 쉽게 풀어 주는 스킬
- 조회형 화면 1~2본으로 효과 검증 실험 ([01 문서](01-효과검증.md))
- 품질 게이트 시제품을 개인 PC pre-commit에 건다
- 보안 담당 부서에 [02 문서](02-보안-제도.md) 기반으로 1차 의견을 받는다

## 2단계: 팀 공용 설정 저장소

개인마다 프롬프트와 규칙이 따로 놀면 결과 품질이 사람마다 달라진다. 에이전트 설정을 **코드처럼 저장소에서 관리**한다.

```
team-agent-config/
├── CLAUDE.md (또는 에이전트 지침 파일)   # 팀 공통 규칙: ES5, 명명 규칙, 금지 사항
├── templates/
│   ├── websquare/   조회형, 등록형, 팝업 화면 기준 템플릿
│   └── sp/          조회·저장·삭제 SP 기준 템플릿
├── schema/          스키마 요약 (DDL에서 자동 추출, 실데이터 없음)
├── skills/
│   ├── generate/    개인 코딩 베이스를 팀 표준으로 다듬은 생성 스킬
│   └── explain/     생성 코드·SP를 쉽게 풀어 주는 설명 스킬
├── commands/        자주 쓰는 작업을 명령으로 (예: /조회화면 생성)
└── gates/           이 저장소의 검사기 (pre-commit, CI 공용)
```

- 1단계에서 효과를 본 **개인 스킬을 팀 공용으로 옮기는 것**이 이 단계의 핵심이다. 개인 습관이 섞인 부분은 팀 표준에 맞게 다듬는다
- 지침과 템플릿을 바꿀 때도 리뷰를 거친다 (프롬프트 변경도 코드 변경으로 취급)
- 스키마 요약은 메타 시스템이나 DDL에서 **자동 생성**해 사람이 손으로 관리하지 않게 한다
- 대상을 단순 CRUD 화면까지 넓힌다. 결재 연동이나 복잡한 트랜잭션은 아직 제외한다
- 사용량, 생성 건수, 게이트 위반 건수를 주 단위로 집계한다

## 3단계: 표준 개발 프로세스 편입

- 개발 표준 문서에 "AI 에이전트 활용 절차" 장을 추가한다
- 검수 절차에 게이트 결과 첨부를 의무화한다 (에이전트를 쓰지 않은 코드에도 같이 적용하면 전체 품질이 오른다)
- LLM 게이트웨이를 운영한다 ([02 문서](02-보안-제도.md) C안)
- 운영 책임: 설정 저장소 관리자, 게이트웨이 운영자, 보안 검토 주기를 정한다
- 외주 개발사 적용 여부와 조건은 별도로 검토한다

## 위험과 대응

| 위험 | 대응 |
|------|------|
| 생성 코드를 이해하지 못한 채 반영 | 설명 스킬로 이해한 뒤 반영 (1단계에서 실제로 효과 확인), 리뷰 체크리스트, 작성자가 검수 때 설명하도록 함 |
| 신규 인력의 기초 역량이 약해짐 | 신규 인력은 일정 기간 기존 방식 병행, 설명 스킬을 학습 도구로 활용 |
| 모델·요금 정책 변경 | 게이트웨이로 모델 교체 가능하게, 온프레미스 PoC 병행 |
| 설정 저장소 방치 | 관리자 지정, 분기별 점검 |
| 효과가 특정 유형 화면에만 국한 | 단계별로 대상 유형을 명시하고, 유형별로 효과를 따로 측정 |
