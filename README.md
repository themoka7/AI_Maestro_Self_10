> **핵심 수치**
> - **시간**: AI 교과목 이수율 조회 화면(공문 요청) 예상 1주 → 실제 반나절 (예상치 대비. 기준값 실측은 TODO)
> - **게이트**: 회귀 시험 9/9건 적발 (ES5 5/5, 개인정보 4/4, 결함 유형 재현 사례). 실업무 건 게이트 결과는 TODO
> - **동료 참여**: TODO(참여 인원·소속)

## 주제

**WebSquare 화면·SP 개발 에이전트 실업무 도입 검토** (7회차 시제품 확장)

7회차 에이전트를 공문 요청 건(AI 교과목 이수율 조회 화면)에 처음 적용해 만들었다. 이 저장소는 그 경험을 근거로, 정보화본부의 학사·행정 시스템 개발 업무에 에이전트를 본격적으로 들일 수 있는지 검토한다.

## 실업무 적용: AI 교과목 이수율 조회 화면

| 항목 | 내용 |
|------|------|
| 요청 | AI 교과목 이수율 조회 화면 개발 (공문 접수) |
| 7회차와의 관계 | 7회차 에이전트의 첫 실업무 적용 건 |
| 화면 유형 | 조회형 (이수율 집계 포함) |
| 범위 | DB 설계, SP 작성, 화면 코드 |
| 예상 공수 | 약 1주 (약 40시간, 기존 방식 기준 추정) |
| 실제 공수 | 반나절 (약 4시간) |
| 기준값 실측 | TODO(과거 유사 조회 화면 실제 공수, SR·커밋 기록 기준) |
| 공문 접수일 | TODO(공문 접수일) |
| 운영 반영일 | TODO(운영 반영일) |
| 운영 상태 | 정상 운영 중 |
| 사용 실적 | TODO(조회 건수·사용 부서 등, 접속 로그 기준) |
| 게이트 결과 | TODO(이 건의 소스로 ES5·개인정보 게이트 실행 결과) |

핵심은 범용 에이전트가 아니라 **스킬**이었다.

| 스킬 | 무엇을 했나 | 효과 |
|------|-----------|------|
| **생성 스킬** | 평소 쓰던 정규식 처리, 공통 패턴 등 다양한 방식의 코드를 정리해 나만의 코딩 베이스로 만들고 스킬로 묶음 | 에이전트가 일반적인 코드가 아니라 **내 방식대로** 만들어서, 생성물을 고치는 시간이 줄어듦 |
| **설명 스킬** | DB 설계와 SP 작성 후, 이해가 안 되는 부분을 쉽게 풀어 달라고 요청 | 모르는 코드를 그대로 반영하지 않고 **이해한 뒤 반영**함. "생성 코드를 이해 못 한 채 반영"하는 위험을 직접 줄임 |

**해석할 때 주의할 점**

- 기준값 1주는 실측이 아니라 **예상치**다. 실측값은 TODO(과거 유사 조회 화면 공수, SR·커밋 기록 기준).
- 사례가 1건이고 조회형 화면이다. 등록·수정형이나 결재 연동 화면은 따로 확인해야 한다.
- 스킬을 직접 만든 사람이 쓴 결과라 효과가 가장 크게 나오는 조건이다.

그래도 연습 과제가 아니라 실제 공문 요청 건을 반영까지 했고, 판단 기준(30% 단축)과 차이가 커서 정식 비교 실험과 확대 검토를 할 근거로는 충분하다. 다음에 확인할 핵심은 **스킬을 만든 본인이 아닌 개발자에게도 같은 효과가 나는가**이다.

## 생성 → 검증 → 수정 루프

에이전트가 코드를 만들면 서브에이전트 [`gate-reviewer`](.claude/agents/gate-reviewer.md)가 게이트를 돌리고, 고칠 수 있는 것은 고치고, 개인정보는 사람에게 넘긴다.

```
 [명세]
   │
   ▼
 생성 (생성 스킬)  ── 화면 XML, SP
   │
   ▼
 ┌─▶ 검사: ES5 게이트 + 개인정보 게이트 ──── 위반 0건 ──▶ [통과] ─▶ SP 리뷰(사람) ─▶ 검수
 │     │
 │     ▼ 위반 있음
 │   분류
 │     ├─ ES5 위반 ──▶ 수정안 작성·적용 ─┐
 │     │                                 │
 │     └─ 개인정보 위반 ──▶ 수정안만 기록 ──▶ [사람 확인 대기] (자동 승인 금지)
 │                                       │
 └──────── 재검사 (최대 3회) ◀────────────┘
                 │
                 └─ 3회 후에도 ES5 위반 남음 ──▶ [실패] ─▶ 사람이 직접 수정
   (매 회차 결과는 logs/gate-review/ 에 기록)
```

| 단계 | AI가 하는 일 | 코드가 하는 일 | 사람이 하는 일 |
|------|-------------|---------------|---------------|
| 생성 | 명세와 생성 스킬로 화면 XML·SP 작성 | | 명세 작성 |
| 검사 | 게이트 실행 지시 | ES5 파싱, 미지원 API·개인정보 컬럼·`SELECT *` 탐지, 종료 코드로 판정 | |
| 수정 | ES5 위반 수정안 작성·적용, 개인정보 위반 수정안 기록 | 재검사로 수정 결과 판정 | |
| 개인정보 | 승인하지 않음, 컬럼을 지어내지 않음 | 승인 주석 없는 접근을 계속 실패 처리 | 컬럼 필요 여부 판단, 승인 근거 기록 |
| 기록 | 회차별 로그 작성 | | 로그 확인 |
| 반영 | 이해 안 되는 부분 설명 (설명 스킬) | | SP 리뷰 체크리스트, 검수 |

판정은 항상 코드(게이트)가 하고, AI는 판정을 바꿀 수 없다. `samples/fail`로 돌린 실행 로그는 [03 문서 3.8](docs/03-품질게이트.md)에 있다.

## 저장소 구성

```
.claude/agents/      gate-reviewer 서브에이전트 정의 (생성 → 검증 → 수정 루프)
docs/                검토 문서 (위 표)
gates/es5/           WebSquare XML·JS의 ES5 문법 검사기 (Node, acorn)
gates/pii/           SP의 개인정보 컬럼 접근 검사기 (Python, 표준 라이브러리만 사용)
scripts/             회귀 시험 실행 스크립트
samples/pass, fail   검사기 동작 확인용 예제
samples/regression/  결함 유형 재현 회귀 시험 사례 (ES5 5건, 개인정보 4건)
samples/loop-demo/   루프 시연 결과물 (samples/fail 복사본을 gate-reviewer가 수정한 상태)
logs/gate-review/    루프 실행 로그
```

## 품질 게이트 실행

```bash
# 준비
cd gates/es5 && npm install && cd ../..

# ES5 검사: WebSquare XML 안의 <script> 블록과 .js 파일을 ES5로 파싱
node gates/es5/check-es5.js samples/pass   # 통과
node gates/es5/check-es5.js samples/fail   # const, includes() 위반 2건

# 개인정보 컬럼 검사: 승인 주석 없이 민감 컬럼을 조회하는 SP를 찾아냄
python3 gates/pii/check_pii.py --columns gates/pii/pii_columns.txt samples/pass   # 통과 (승인 주석 있는 SP 포함)
python3 gates/pii/check_pii.py --columns gates/pii/pii_columns.txt samples/fail   # SELECT *, 미승인 MOBILE_NO·EMAIL 3건

# 회귀 시험: 결함 유형 재현 사례를 두 게이트로 돌려 "적발 n/m건" 표 출력
python3 scripts/regression.py
```

게이트와 회귀 시험 모두 위반이나 놓침이 있으면 종료 코드 1을 반환하므로, pre-commit 훅이나 CI 단계에 그대로 걸 수 있다.
