# 8회차 · AI Agent 도입 가능성 검토 및 확장 토의

## 주제

**WebSquare 화면·SP 개발 에이전트 실업무 도입 검토** (7회차 시제품 확장)

7회차에 만든 "WebSquare 화면 + 저장 프로시저(SP) 생성 에이전트" 시제품을 정보화본부의 학사·행정 시스템 개발 업무에 본격적으로 들일 수 있는지 검토한다. 이미 공문으로 들어온 개발 요청 1건(AI 교과목 이수율 조회 화면)에 적용해 실업무에 반영했다.

📄 **리포트(한 페이지 요약)**: https://claude.ai/artifact/8y8mJM52yp5CcaL7SxssyD (비공개 링크, 공유 설정 필요)

## 핵심 결과: 예상 1주 → 실제 반나절

**실업무 적용 사례: AI 교과목 이수율 조회 화면 (공문 요청)**

공문으로 접수된 개발 요청을 7회차 에이전트로 처리해 실업무에 반영했다. DB 설계, SP 작성, 화면 코드까지 기존 방식으로 **약 1주(약 40시간)** 걸릴 것으로 예상했던 작업을 **반나절(약 4시간)** 에 끝냈다. 예상치 대비 약 90% 단축이다.

핵심은 범용 에이전트가 아니라 **스킬**이었다.

| 스킬 | 무엇을 했나 | 효과 |
|------|-----------|------|
| **생성 스킬** | 평소 쓰던 정규식 처리, 공통 패턴 등 다양한 방식의 코드를 정리해 나만의 코딩 베이스로 만들고 스킬로 묶음 | 에이전트가 일반적인 코드가 아니라 **내 방식대로** 만들어서, 생성물을 고치는 시간이 줄어듦 |
| **설명 스킬** | DB 설계와 SP 작성 후, 이해가 안 되는 부분을 쉽게 풀어 달라고 요청 | 모르는 코드를 그대로 반영하지 않고 **이해한 뒤 반영**함. "생성 코드를 이해 못 한 채 반영"하는 위험을 직접 줄임 |

**해석할 때 주의할 점**

- 기준값 1주는 실측이 아니라 **예상치**다.
- 사례가 1건이고 조회형 화면이다. 등록·수정형이나 결재 연동 화면은 따로 확인해야 한다.
- 스킬을 직접 만든 사람이 쓴 결과라 효과가 가장 크게 나오는 조건이다.

그래도 연습 과제가 아니라 실제 공문 요청 건을 반영까지 했고, 판단 기준(30% 단축)과 차이가 커서 정식 비교 실험과 확대 검토를 할 근거로는 충분하다. 다음에 확인할 핵심은 **스킬을 만든 본인이 아닌 개발자에게도 같은 효과가 나는가**이다.

## 저장소 구성

```
docs/            검토 문서 (위 표)
gates/es5/       WebSquare XML·JS의 ES5 문법 검사기 (Node, acorn)
gates/pii/       SP의 개인정보 컬럼 접근 검사기 (Python, 표준 라이브러리만 사용)
samples/         검사기 동작 확인용 예제 (통과·실패 각 1건)
```

## 품질 게이트 실행

```bash
# ES5 검사: WebSquare XML 안의 <script> 블록과 .js 파일을 ES5로 파싱
cd gates/es5 && npm install && cd ../..
node gates/es5/check-es5.js samples/pass   # 통과
node gates/es5/check-es5.js samples/fail   # const, includes() 위반 2건

# 개인정보 컬럼 검사: 승인 주석 없이 민감 컬럼을 조회하는 SP를 찾아냄
python3 gates/pii/check_pii.py --columns gates/pii/pii_columns.txt samples/pass   # 통과 (승인 주석 있는 SP 포함)
python3 gates/pii/check_pii.py --columns gates/pii/pii_columns.txt samples/fail   # SELECT *, 미승인 MOBILE_NO·EMAIL 3건
```

두 검사기 모두 위반이 있으면 종료 코드 1을 반환하므로, pre-commit 훅이나 CI 단계에 그대로 걸 수 있다.
